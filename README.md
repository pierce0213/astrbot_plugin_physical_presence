# 现实人生・astrbot\_plugin\_physical\_presence v2.3.3

> GitHub：<https://github.com/pierce0213/astrbot_plugin_physical_presence>
> 插件市场：搜索「现实人生」即可安装（发布页：<https://cloud.astrbot.app/publish>）

一个插件，把 AstrBot 从屏幕那边接回现实：她有自己的日程、地点、距离、接触和跨轮动作；你在哪由你自己说。

v2.2 的关键变化：**她主导，你在哪由你自己说**。插件不再替你安排位置、姿势和手里的东西。

它现在自己就会：



* 按人格生成每天的日程、主题、心情、穿搭；

* 按时间线安排她在哪、在做什么、可不可打扰；

* 到点发主动消息，带重试、空闲判断、发送限制、消息分段；

* 按可打扰程度延迟回复、合并批次；

* 管理「大时间表」长期阶段（生成、草稿、批准、拒绝、重载）；

* 渲染日程图、穿搭图；

* 解析当前会话人格，接人际网络；

* 再加一层身体：地点、距离、姿势、手边物品、接触部位、没做完的动作、去屏幕化。

日程、穿搭、主动消息、回复延迟、长期阶段、图片渲染由内置引擎提供；
该引擎部分基于 Florance 的 `astrbot_plugin_virtual_life` v1.12.2（GPL-3.0），已并入 `vlcore/`；身体层是本插件自己的。

完整署名见 `NOTICE.md` 与 `LICENSE`。

## 安装

1. 把本文件夹放进 `<AstrBot 安装目录>/data/plugins/`

2. AstrBot 面板 → 插件管理 → 重载本插件；或重启 AstrBot。

3. 打开本插件配置，确认出现 17 个分组：

   身体现场、她的一天、手边物品、动作导演、去屏幕化、亲密尺度，

   以及日程、长期阶段、主动消息、回复延迟、图片、智能注入等。

4. 发 `/现实 状态` 和 `/虚拟日程 查看`，都能出东西。

第一次加载会在下面这个目录建立数据：

```
<AstrBot 安装目录>/data/plugin_data/astrbot_plugin_physical_presence
```

里面会有 `states.json`（当前身体现场）和 `plans.json`（每天的日程与穿搭）。

## 它是什么

这不是一个角色卡，也不是一个聊天前端。

它给 AstrBot 里的“她”补上一层身体：

* 她现在在哪、什么姿势、离你多远；
* 她手里有没有东西、东西在哪、还剩多少；
* 你们有没有碰到、碰到哪里、用了多大力；
* 上一轮没做完的动作，下一轮还记不记得；
* 她去上课、回家、去食堂，地点会不会跟着变。

聊天里仍然只有动作和台词；状态块只给模型看，发送前会被剥掉。

## 身体层怎么工作：她主导，你说你在哪

这层不替用户造一个 “分身”。她有自己的地点、日程、姿势和手边的东西；

你在哪、在做什么、手里有什么，**只有你自己说了才记录**。你没说，现场就留白，

她可以先问一句，而不是先替你坐下、替你拿可乐。

每轮在引擎注入 `<character_state>` 之后，再追加：



```
<physical_state>
【此刻】19:15，晚上；只开了一盏落地灯；室内24°C。
【地方】她在家里，客厅，沙发和茶几之间。
【她】盘腿坐在地毯上，背靠着沙发。
【你】还没说你此刻在哪。不要替他安排位置、姿势、手里拿着什么；
      他没说就留白，或先问一句。
【她此刻在做】阅读与写点小散文。
【她今天穿】白衬衫配深蓝背心……
【她可以主动】她可以先问你在哪、在忙什么；不要替他编位置。
</physical_state>
```

环境里的东西不列清单。她真拿在手里才写 `【她手里】`；茶几、冰箱、玄关的东西，
等她要用时由动作带出来（开冰箱、拿一罐、把碗往你这边推）。

你如果说 “我在公司 / 我不在家 / 我在教室 / 我刚到家”，插件才把

`【你】` 写成对应位置：



* 你和她同处：`【你】你在家里；【她】……离你 40 厘米`，可以接触；

* 你和她不在一处：`【你】你在公司，不在这里`，协议禁止碰到她、递东西到她手里；

* 你一直没说：只写她那边，不写你的姿势，也不写 “你手里”。

模型每轮末尾输出 `<phys>{...}</phys>`，插件剥掉并写回：



* 东西换手、液位、温度、备注；

* 接触全量替换 / 追加 / 解除；

* 距离、当前活动、没做完的动作。

只有你明确说 “我接过了 / 我喝了”，插件才把东西从她手里移到你手里；

她只是 “递到你手边” 时，东西仍在她手里，并记成 `pending`。下一轮她还记得这罐可乐。

没写状态块时，从（）动作里猜最明显的变化，但不会凭 “递给你” 就认定你已经接了。

### 场景

`core/places.py` 注册 11 个地点：家里、厨房、院子、教室、图书馆、食堂、

公交车、便利店、公园、街上、办公室。日程里的「宿舍书桌 / 教学楼 302 /

第二食堂 / 公交 27 路 / 旧书街区」都会映射到对应场景，并换掉手边道具。

她的位置由她的日程决定；你的位置由你的话决定。两者相同才同处，不同就分开。

不再用 `follow_mode` 强行 “她去哪你跟到哪”。配置里的 `user_state_mode`：



* `unknown`（默认）：你没说，她就不知道你在哪；

* `assume_home`：只在她也在家时默认你在家；她在学校时仍然分开。

分开时协议禁止碰到她、递东西给她，现场只写她这边。

### 代码结构



* `main.py`：AstrBot 钩子、命令、引擎启动与数据读写，不写具体物理规则；

* `core/`：身体层，管状态、位置、物品、动作回写、去屏幕化；

* `core/context.py`：只决定 “这轮发全量还是压缩”，不掺业务；

* `vlcore/`：内置的日程、穿搭、主动消息、图片等引擎，独立于身体层。

身体层不重新生成日程，只读引擎的 `plan`；引擎也不依赖身体层，关掉身体层仍能单独工作。

身体层启用时，插件会停用旧的 `<character_state>` 注入，只保留一份 `<physical_state>`，

避免模型同时看到 “屏幕里的她” 和 “身边的她”。

不在一处时，回复后处理会把 “碰到你、递到你手里、手伸出来” 改成一句距离边界：

她够不到你，先问你在哪；等你说 “我接过了 / 我喝了”，东西才会真的转到他手里。

### 上下文预算

`core/context.py` 只做一件事：决定这一轮发全量还是压缩。



* 第一次：全量现场 + 完整协议；
* 换地点、换姿势、换活动：全量现场 + 三行协议；
* 只换手里的东西、接触变化：压缩现场 + 三行协议；
* 稳定轮：只发现场变化 + 三行协议。

实测同一现场：

* 第一次约 695 字符；
* 换地点约 480 字符；
* 只换道具约 260 字符；
* 稳定轮约 235 字符，不到第一次的 35%；
* 稳定轮不再重复 “你们之间” 的长期事实，也不重复整份手边清单；
* 穿搭不每轮注入，问到时由 `get_her_outfit` 工具或 `/现实 穿搭` 取。

这不是靠删信息省 token，而是把 “每轮都必须知道的” 和 “变了才需要知道的” 分开。

### 回复节奏

协议要求她主导、一条 1–2 句、最多一个动作，不再逼模型每条都堆动作。

动作写到部位、力度、温度；拿东西先写从哪拿；够不着就先挪近或起身。

### 去屏幕化



* 注入改写：`宿舍→家里`、`视频吃晚饭→一起吃晚饭`、`书桌→桌上`、

  `隔着屏幕→面对面`；

* 回复过滤：手机、屏幕、消息、语音、视频、表情包、在线等整句删掉，

  删空了用兜底句接住；

* 发送前再兜底剥一次 `<phys>` 块。

## 配置分组

身体层 6 组：



| 分组      | 关键项                           |
| ------- | ----------------------------- |
| 📍 物理现场 | 启用、初始地点、距离、室温、光线、她的姿势、你在哪由谁决定 |
| 🗓 她的一天 | 日程来源、身份、人格名、分开距离              |
| 🧺 手边物品 | 初始道具、长期身体事实、接触过期时间            |
| ✋ 动作导演  | 强制动作、历史条数、状态块开关               |
| 🖥 去屏幕化 | 改写注入、改写回复、额外禁词                |
| 💗 亲密尺度 | 日常 / 亲近、兜底句                   |

引擎 11 组：

`schedule_settings`、`personal_network_integration`、`prompt_settings`、

`creative_pool`、`long_term_settings`、`image_settings`、

`reply_delay_settings`、`smart_context_injection`、

`friend_settings`、`group_settings`、`delivery_settings`。

建议先设：



* `她的一天 → 对应的人格名`：`莉莉（女友）`

* `物理现场 → 你在哪由谁决定`：先用 `unknown`；只有你想默认在家才改 `assume_home`

* `智能注入 → 启用`：保持开启

* `普通回复延迟 → 启用`：按你想要的速度开

## 边界



* 不做露骨性描写；牵手、拥抱、亲吻、靠肩、捂脚、一起睡等正常亲密照写。

* 分开时绝不伪造接触。

* 引擎沿用虚拟人生原配置语义；主动消息的发送对象仍是已订阅会话。
